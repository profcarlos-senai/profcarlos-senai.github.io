# Tutorial 3: Conexão com o banco de dados e CRUD

Seja bem-vindo ao terceiro tutorial! Hoje vamos conectar nossa aplicação ao banco de dados relacional **PostgreSQL**, transformar a classe `Pessoa` em uma entidade JPA com chave primária auto-incrementável (`SERIAL`), popular a tabela usando `data.sql` e criar os endpoints do CRUD um a um.

CRUD significa Criar, Recuperar, atUalizar e Deletar

## Passo 1: Configurando as Dependências no `pom.xml`

```text
meuprojeto
└── pom.xml  <-- Adicionar as novas dependências aqui

```

Abra o arquivo `pom.xml` e adicione as dependências do **Spring Data JPA** e do driver do **PostgreSQL** dentro do bloco `<dependencies>`:


> ### IMPORTANTE
> Você deve adicionar esse bloco de código entre `<dependencies>` e `</dependencies>` no seu `pom.xml`

```xml
<!-- Spring Data JPA -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-data-jpa</artifactId>
</dependency>

<!-- Driver PostgreSQL -->
<dependency>
    <groupId>org.postgresql</groupId>
    <artifactId>postgresql</artifactId>
    <scope>runtime</scope>
</dependency>

```

Depois de salvar o arquivo `pom.xml` você precisa clicar no botãozinho do maven ![botão do maven](image.png) que aparece acima e a direita. Isso vai baixar as dependências novas que você colocou.

## Passo 3: Transformando a Classe `Pessoa` em uma Entidade

```text
meuprojeto
└── src
    └── main
        └── java
            └── br
                └── senai
                    └── meuprojeto
                        └── modelo
                            └── Pessoa.java  <-- Mapear como Entidade JPA aqui

```

Precisamos mapear a classe `Pessoa` para virar uma tabela no PostgreSQL com chave primária (`id`) auto-incrementável.

Explicação das novas anotações:

* `@Entity`: Informa ao Spring JPA que esta classe é uma tabela no banco de dados.
* `@Table(name = "pessoa")`: Define explicitamente o nome da tabela no banco.
* `@Id`: Marca o atributo como chave primária da tabela.
* `@GeneratedValue(strategy = GenerationType.IDENTITY)`: Define que a geração da chave primária é gerenciada pelo banco de dados no modo autoincremento (`SERIAL` no PostgreSQL).

Atualize o arquivo `src/main/java/br/senai/meuprojeto/modelo/Pessoa.java`:

```java
package br.senai.meuprojeto.modelo;

import jakarta.persistence.Entity;
import jakarta.persistence.GeneratedValue;
import jakarta.persistence.GenerationType;
import jakarta.persistence.Id;
import jakarta.persistence.Table;

import java.math.BigDecimal;
import java.time.LocalDate;

@Entity
@Table(name = "pessoa")
public class Pessoa {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String nome;
    private String telefone;
    private int idade;
    private LocalDate dataContrato;
    private BigDecimal salario;

    // Construtor vazio (obrigatório para o JPA)
    public Pessoa() {
    }

    // Construtor completo
    public Pessoa(Long id, String nome, String telefone, int idade, LocalDate dataContrato, BigDecimal salario) {
        this.id = id;
        this.nome = nome;
        this.telefone = telefone;
        this.idade = idade;
        this.dataContrato = dataContrato;
        this.salario = salario;
    }

    // Getters e Setters
    public Long getId() {
        return id;
    }

    public void setId(Long id) {
        this.id = id;
    }

    public String getNome() {
        return nome;
    }

    public void setNome(String nome) {
        this.nome = nome;
    }

    public String getTelefone() {
        return telefone;
    }

    public void setTelefone(String telefone) {
        this.telefone = telefone;
    }

    public int getIdade() {
        return idade;
    }

    public void setIdade(int idade) {
        this.idade = idade;
    }

    public LocalDate getDataContrato() {
        return dataContrato;
    }

    public void setDataContrato(LocalDate dataContrato) {
        this.dataContrato = dataContrato;
    }

    public BigDecimal getSalario() {
        return salario;
    }

    public void setSalario(BigDecimal salario) {
        this.salario = salario;
    }
}

```

Você também vai precisar alterar o código em `controle.PessoaControler.java` para conseguir rodar (adicionar o valor `null` para o id):
```java
    @GetMapping
    public Pessoa getPessoa() {

                null,
                "Carlos Eduardo",
                "(41) 99999-8888",
                28,
                LocalDate.of(2023, 3, 15),
                new BigDecimal("4500.50")
        );
    }
```

## Endpoint 1: Alterando `getPessoa` para Listar Todas as Pessoas

### Explicação das Novas Anotações e Métodos:

* `@Autowired`: Injeta automaticamente a instância gerenciada pelo Spring do `PessoaRepository` na variável.
* `pessoaRepository.findAll()`: Método nativo do Spring Data JPA que executa uma consulta SQL (`SELECT * FROM pessoa`) e retorna uma lista com todos os registros cadastrados.

### Código Java em `PessoaController.java`

:

```java
package br.senai.meuprojeto.controle;

import br.senai.meuprojeto.modelo.Pessoa;
import br.senai.meuprojeto.repositorio.PessoaRepository;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.web.bind.annotation.*;

import java.util.List;

@RestController
@RequestMapping("pessoa")
public class PessoaController {

    @Autowired
    private PessoaRepository pessoaRepository;

    // Retorna a lista completa de pessoas do banco
    @GetMapping
    public List<Pessoa> getPessoa() {
        return pessoaRepository.findAll();
    }
}

```

## Endpoint 2: Criando `getPessoaPorId`

### Explicação das Novas Anotações e Métodos:

* `pessoaRepository.findById(id)`: Busca um registro pelo ID no banco. Retorna um objeto `Optional<Pessoa>`, pois o registro pode não existir.
* `ResponseEntity.ok(...)`: Retorna uma resposta HTTP `200 OK` com o objeto localizado no corpo da resposta.
* `ResponseEntity.notFound().build()`: Retorna o status HTTP `404 Not Found` caso o registro não seja localizado.

### Código Java para adicionar ao `PessoaController.java`

:

```java
    // Retorna uma pessoa específica através do ID
    @GetMapping("{id}")
    public ResponseEntity<Pessoa> getPessoaPorId(@PathVariable Long id) {
        return pessoaRepository.findById(id)
                .map(pessoa -> ResponseEntity.ok(pessoa))
                .orElse(ResponseEntity.notFound().build());
    }

```

## Endpoint 3: Criando `criaPessoa` (POST)

### Explicação das Novas Anotações e Métodos:

* `@PostMapping`: Mapeia requisições HTTP do tipo `POST`.
* `@RequestBody`: Converte automaticamente o corpo do JSON enviado na requisição num objeto Java `Pessoa`.
* `pessoaRepository.save(pessoa)`: Salva a nova entidade no banco. Como a propriedade `id` é nula no momento do envio, o Hibernate executará um `INSERT` e retornará a pessoa com o `id` preenchido.
* `HttpStatus.CREATED`: Define o código de retorno HTTP `201 Created`.

### Código Java para adicionar ao `PessoaController.java`

:

```java
    @PostMapping
    @ResponseStatus(HttpStatus.CREATED)
    public Pessoa criaPessoa(@RequestBody Pessoa pessoa) {
        return pessoaRepository.save(pessoa);
    }

```

## Endpoint 4: Criando `alteraPessoa` (PUT)

### Explicação das Novas Anotações e Métodos:

* `@PutMapping("{id}")`: Mapeia requisições HTTP do tipo `PUT` com a inclusão da variável de caminho `{id}`.
* `pessoaRepository.existsById(id)`: Verifica se um registro com determinado ID já existe no banco.
* `pessoa.setId(id)`: Garante que o objeto recebido assuma o ID informado na URL antes de ser salvo.
* `pessoaRepository.save(pessoa)`: Quando chamado com um objeto que já possui `id`, o Spring Data JPA executa uma instrução de atualização (`UPDATE`).

### Código Java para adicionar ao `PessoaController.java`

:

```java
    @PutMapping("{id}")
    public ResponseEntity<Pessoa> alteraPessoa(@PathVariable Long id, @RequestBody Pessoa pessoa) {
        if (!pessoaRepository.existsById(id)) {
            return ResponseEntity.notFound().build();
        }
        pessoa.setId(id);
        Pessoa pessoaAtualizada = pessoaRepository.save(pessoa);
        return ResponseEntity.ok(pessoaAtualizada);
    }

```

## Endpoint 5: Criando `deletaPessoa` (DELETE)

### Explicação das Novas Anotações e Métodos:

* `@DeleteMapping("{id}")`: Mapeia requisições HTTP do tipo `DELETE`.
* `pessoaRepository.deleteById(id)`: Exclui o registro correspondente ao ID informado diretamente do banco de dados (`DELETE FROM pessoa WHERE id = ?`).
* `ResponseEntity.noContent().build()`: Retorna a resposta com o código `204 No Content`, indicando sucesso no processamento sem retorno de conteúdo no corpo da resposta.

### Código Java para adicionar ao `PessoaController.java`

:

```java
    @DeleteMapping("{id}")
    public ResponseEntity<Void> deletaPessoa(@PathVariable Long id) {
        if (!pessoaRepository.existsById(id)) {
            return ResponseEntity.notFound().build();
        }
        pessoaRepository.deleteById(id);
        return ResponseEntity.noContent().build();
    }

```
